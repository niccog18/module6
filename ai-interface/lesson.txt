Learning Objectives

By the end of this lesson, you will be able to:

    Build a chat interface using st.chat_message() and st.chat_input()
    Store and re-render chat history using session state
    Connect to the OpenAI API for real AI responses (or use a mock fallback)
    Stream responses in real-time using st.write_stream()

This is the lesson everything has been building toward. You’re about to combine everything you’ve learned - Streamlit widgets, session state, API calls, layout - into the kind of interface that powers ChatGPT, Claude, and every AI chatbot you’ve used.

The architecture is simpler than you might expect. A chat interface is just: a list of messages stored in session state, a text input for the user, an API call to get the AI’s response, and a loop that re-renders the full history on every run.
Chat Components

Streamlit has purpose-built components for chat interfaces:
# Display a message from the user
with st.chat_message("user"):
    st.write("What is Python?")

# Display a message from the assistant
with st.chat_message("assistant"):
    st.write("Python is a high-level programming language...")

# Text input pinned to the bottom of the page
prompt = st.chat_input("Ask me anything...")

st.chat_message() creates a message bubble with an avatar (user or assistant icon). st.chat_input() creates a text input pinned to the bottom of the screen - just like a real chat app.
The Chat History Pattern

Here’s why session state is essential. Streamlit re-runs the entire script on every interaction. When the user sends a message, the script re-runs, and all previously displayed messages vanish unless you explicitly re-render them.

The solution: store all messages in session state and re-render them on every run:
# Initialize chat history
if "messages" not in st.session_state:
    st.session_state["messages"] = []

# Re-render ALL previous messages on every run
for message in st.session_state["messages"]:
    with st.chat_message(message["role"]):  # "user" or "assistant"
        st.write(message["content"])

# Handle new user input
if prompt := st.chat_input("Ask me anything..."):  # := is the walrus operator
    # Add user message to history
    st.session_state["messages"].append({"role": "user", "content": prompt})
    with st.chat_message("user"):
        st.write(prompt)

    # Get AI response and add to history
    response = get_ai_response(prompt)
    st.session_state["messages"].append({"role": "assistant", "content": response})
    with st.chat_message("assistant"):
        st.write(response)

The := is Python’s walrus operator - it assigns the value of st.chat_input() to prompt and simultaneously checks if it’s truthy (not None or empty). It’s equivalent to:
prompt = st.chat_input("Ask me anything...")
if prompt:
    ...
Streaming Responses

Real AI APIs stream responses token-by-token. Streamlit’s st.write_stream() handles this elegantly:
import openai

client = openai.OpenAI(api_key=api_key)

stream = client.chat.completions.create(
    model="gpt-3.5-turbo",
    messages=st.session_state["messages"],
    stream=True  # Enable streaming
)

# st.write_stream displays each chunk as it arrives
with st.chat_message("assistant"):
    response = st.write_stream(stream)  # Returns the full text when done

st.write_stream() accepts a generator (an object that yields chunks of text) and displays each chunk as it arrives — creating the typing effect you see in ChatGPT.
API Keys: st.secrets and Input Fields

For development, you can accept API keys via a sidebar input:
with st.sidebar:
    api_key = st.text_input("OpenAI API Key", type="password")

The type="password" masks the input so the key isn’t visible on screen.

For deployed apps, use st.secrets — Streamlit’s built-in secret management:
# In .streamlit/secrets.toml:
# OPENAI_API_KEY = "sk-..."

api_key = st.secrets["OPENAI_API_KEY"]

Never hardcode API keys in your source code.
Mock Responses for Students Without API Keys

Not everyone will have an OpenAI API key. A good AI interface app should include a mock fallback:
import time

def mock_stream(prompt):
    """Generate a fake streaming response for demo purposes."""
    response = f"This is a mock response to: '{prompt}'. In a real app, this would come from an AI model like GPT or Claude."
    for word in response.split():
        yield word + " "
        time.sleep(0.05)  # Simulate streaming delay

This lets students build and test the full chat interface without needing an API key.
